# AI Design System - 技術アーキテクチャガイド

> このドキュメントは、非エンジニアの方でもプロジェクトの全体像を理解できるように書かれています。

## このプロジェクトは何をするもの？

**AI Design System** は、プロダクトの見た目やUI部品（ボタン、入力欄など）を統一するための「デザインシステム」です。

普通のデザインシステムと違う点は、**AIツール（Claude、Cursorなど）がデザインの知識を直接参照できる**ことです。たとえば、AIに「ボタンを作って」と頼むと、このデザインシステムの色やサイズのルールに従ったコードを自動生成してくれます。

### デザインシステムが解決する問題

| 問題 | デザインシステムがある場合 |
|------|--------------------------|
| 「このボタンの色は何？」と毎回聞く | トークン（設計値）を見ればわかる |
| 画面ごとにボタンの見た目が違う | 共通コンポーネントで統一される |
| AIが勝手なデザインでコードを書く | MCPサーバー経由で正しいルールを参照する |

---

## なぜモノレポ構成なのか？

**モノレポ**（複数のパッケージを1つのリポジトリで管理する構成）を採用しています。

```
ai-design-system/          <-- 1つのリポジトリ
  packages/
    tokens/                <-- パッケージ1: デザインの値
    components/            <-- パッケージ2: UI部品
    mcp-server/            <-- パッケージ3: AI連携
  apps/
    storybook/             <-- アプリ: カタログサイト
```

### モノレポのメリット

- **一括管理**: 色を変えたら、それを使うボタンも同じリポジトリ内で即座に更新できる
- **バージョンの整合性**: 各パッケージが常に最新の状態で連携する
- **開発効率**: `bun run build` 一つで全パッケージがビルド（変換・出力）される

### 使っているツール

| ツール | 役割 |
|--------|------|
| **bun** | パッケージマネージャー（ライブラリの管理・スクリプト実行） |
| **Turborepo** | モノレポのビルドを高速化するツール。依存関係を考慮して効率的にビルドする |
| **TypeScript** | JavaScriptに型（データの種類の指定）を追加した言語 |
| **Biome** | コードの書き方を自動チェック・整形するツール |

## 各パッケージの役割

### 1. `packages/tokens` - デザイントークン

**デザイントークン**とは、色・フォント・余白・影などの「デザインの値」をコードとして定義したものです。

```
例: colors.ts で定義されている色
  - gray: #ffffff（白）〜 #000000（黒）の12段階
  - blue: ブランドカラー（プライマリ）
  - purple: AI機能を示すアクセントカラー（#9333ea）
  - red / green / yellow: エラー・成功・警告の意味色
```

トークンはさらに「セマンティックカラー（意味のある色名）」に変換されます:
- `primary.default` → 主要なアクション色（青）
- `ai.default` → AI機能を示す色（紫）
- `error.default` → エラーを示す色（赤）

**このパッケージの出力物:**
- TypeScriptから参照できるトークンオブジェクト
- CSSカスタムプロパティ（`--color-primary-default` のような変数）ファイル

### 2. `packages/components` - UIコンポーネント

**コンポーネント**（再利用可能なUI部品）を提供します。現在は3つのコンポーネントがあります:

| コンポーネント | 説明 | 特徴 |
|-------------|------|------|
| **Button** | ボタン | 5種類のバリエーション（primary / secondary / ghost / destructive / ai） |
| **Badge** | ラベル・バッジ | ステータス表示用（success / error / warning / ai / outline） |
| **Input** | テキスト入力欄 | ラベル・エラー・ヒント表示対応 |

全コンポーネントは `@ai-component` というタグを持ち、AIツールが自動的に発見できるようになっています。

### 3. `packages/mcp-server` - MCPサーバー（AI連携）

**MCP**（Model Context Protocol）は、AIツールが外部の知識を参照するための仕組みです。

このサーバーを起動すると、ClaudeやCursorなどのAIツールが以下の操作をできるようになります:

| MCPツール名 | できること |
|------------|-----------|
| `list_components` | 使えるコンポーネントの一覧を取得 |
| `get_component` | コンポーネントの使い方・プロパティを取得 |
| `get_tokens` | デザイントークンをカテゴリ別に取得 |
| `get_token_value` | 特定のトークンの値を取得（例: `semanticColors.primary.default`） |

### 4. `apps/storybook` - Storybook（コンポーネントカタログ）

**Storybook** は、コンポーネントを一覧表示して動作確認できるカタログサイトです。ブラウザで `http://localhost:6006` にアクセスして使います。

- デザイナーがコンポーネントの見た目を確認する場所
- 各コンポーネントのバリエーション・サイズ・状態を視覚的に確認できる

## パッケージ間の依存関係

```
                    ┌──────────────────┐
                    │  apps/storybook  │
                    │  (カタログサイト)  │
                    └────┬────────┬────┘
                         │        │
                    依存する   依存する
                         │        │
                         v        │
               ┌─────────────────┐│
               │ packages/       ││
               │ components      ││
               │ (UI部品)        ││
               └────────┬────────┘│
                        │         │
                   依存する       │
                        │         │
                        v         v
               ┌─────────────────────┐
               │  packages/tokens    │
               │  (デザインの値)     │
               └──────────┬──────────┘
                          │
                     参照する
                          │
                          v
               ┌─────────────────────┐
               │ packages/mcp-server │
               │ (AI連携サーバー)    │
               └─────────────────────┘
```

**読み方:**
1. `tokens`（デザインの値）が土台。色・余白・フォントなどの値を定義する
2. `components`（UI部品）は `tokens` の値を使ってボタンや入力欄を作る
3. `mcp-server`（AI連携）は `tokens` の値を参照して、AIに情報を提供する
4. `storybook`（カタログ）は `tokens` と `components` の両方を使って、カタログサイトを表示する

## コマンド一覧

| コマンド | 何をするか |
|---------|-----------|
| `bun install` | 必要なライブラリをインストール |
| `bun run build` | 全パッケージをビルド（出力ファイル生成） |
| `bun run storybook` | Storybookを起動（ブラウザで確認） |
| `bun run tokens:build` | トークンからCSSファイルを再生成 |
| `bun run dev` | 開発モード（ファイル変更を自動検知） |
